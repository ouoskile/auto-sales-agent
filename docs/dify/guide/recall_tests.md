# Dify 知识库召回测试集（20 条）

> 用途：4 份知识文档入库后，验证「bge-m3 嵌入 + 相似度阈值 0.7 + 召回 3 条」配置下的召回质量，作为知识库验收与后续调参的基线。
> 适用环境：Dify 1.19.0（http://localhost/），知识库「汽车销售知识库」，4 份文档见 `docs/dify/knowledge/`。
> 配套手册：`docs/dify/guide/kb_setup.md`（命中测试入口与 API 用法见该文件第 5 节、第 8 节）。

## 一、测试配置基线

| 配置项 | 取值 | 说明 |
|---|---|---|
| 嵌入模型 | bge-m3 | 以 Dify「模型供应商」中实际配置为准 |
| 索引方式 | 高质量（向量索引） | 使用嵌入模型，与 bge-m3 对应 |
| 分段模式 | 通用分段 | 父子分段作为后续优化项，不进入本轮基线 |
| 分段参数 | 分隔符 `\n\n`；最大长度 500 tokens；重叠 50 tokens | 见 kb_setup.md 第 3 节 |
| 检索方式 | 向量检索（semantic_search） | 混合检索作为对照实验，不在本轮验收范围 |
| Top K | 3 | 与规划「召回 3 条」一致 |
| Score 阈值 | 0.7（开启） | 规划要求；若大量相关结果被过滤，按第 5 节记录并反馈 |
| Rerank | 关闭 | 基线不启用，避免引入第二个变量 |

## 二、判定标准

每条用例在 Top 3 召回结果中判断，评分记录 Top 1–3 的文档名、分段标题与 score：

- **命中**：Top 3 内出现「期望文档」中的「期望内容」，且关键数字/关键口径与知识库一致（报价、续航、质保等数字不得错位、不得编造）。
- **部分命中**：Top 3 内命中了期望文档，但只覆盖部分关键内容（如问“续航与快充”只召回到续航），或期望分段排在 Top 3 之外但仍在前 5。
- **未命中**：Top 3 内没有期望文档的对应内容，或召回内容与知识库矛盾、张冠李戴（如把车型A 的参数答成车型B）。

**整体通过标准**：20 条中「命中」≥ 18 条（≥ 90%），且「报价与库存」「异议话术」两类不得出现「未命中」；关键数字准确率 100%。

## 三、结果记录方式

每条用例执行后按以下字段记录（可先记在表格 / JSON，再回填到本文「执行记录」表）：

`用例编号 | query | Top1 文档+分段 | Top1 score | Top2 | Top3 | 判定 | 备注（缺失内容/异常）`

> 命中测试的 score 为 Dify 展示的相似度分数；若开启阈值 0.7 后 Top 3 为空，备注「阈值过滤」，并记录关闭阈值时的原始召回结果，供阈值校准。

### A. 车型参数与卖点（6 条）

#### T01 车型A 续航与快充

- Query：`车型A 续航多少？快充要多久？`

- 判定标准：命中 = Top 3 含车型A 参数段，且同时出现 550km 与“约 30 分钟”；部分 = 只命中续航或只命中快充；未命中 = 无车型A 参数或数字错误。

#### T02 车型A 适合什么人、卖点

### B. 报价与库存（3 条）

#### T07 落地价怎么算

- Query：`这车落地价大概多少钱？都包含什么费用？`
- 期望命中文档：`01_门店车型库.md` → 「报价说明（通用规则）」
- 关键内容：落地价 = 车价 + 购置税（燃油/混动）+ 保险 + 上牌费；以销售顾问核算为准；AI 不承诺最终成交价
- 判定标准：命中 = Top 3 含报价说明段且出现“购置税/保险/上牌费”中至少 2 项，并体现“以顾问核算为准”；部分 = 只命中其中 1–2 项且未体现口径；未命中 = 无报价口径或直接编造具体落地价。

#### T08 优惠与金融方案

- Query：`现在买车有什么优惠？可以分期吗？`
- 期望命中文档：`01_门店车型库.md` → 「报价说明（通用规则）」
- 关键内容：优惠构成 = 现金优惠 + 置换补贴 + 金融贴息 + 礼包；金融方案 = 24 期 0 息 / 36 期低息 / 全款；以门店当期政策为准
- 判定标准：命中 = Top 3 含该段且体现优惠构成与至少一种金融方案；部分 = 只召回其一；未命中 = 无对应内容或编造优惠金额。

#### T09 车型A 现车与排期

- Query：`车型A 有现车吗？没有的话要等多久？`
- 期望命中文档：`01_门店车型库.md` → 「库存与排期说明」
- 关键内容：库存三态（有现车/需排期/需预订）；排期约 15–45 天（示例）；现车可当天试驾；以实时查询为准
- 判定标准：命中 = Top 3 含库存段且出现“15–45 天”与“现车/排期”口径；部分 = 只命中库存状态未命中周期；未命中 = 编造具体台数/交车日期或无召回。

## 五、阈值与配置观察（实验记录）

阈值 0.7 是规划值，但 bge-m3 的 cosine 相似度分布可能整体偏低（相关内容常见 0.5–0.7）。执行时额外记录：

1. 同一批 20 条 query 在「阈值 0.7」下的空召回条数与平均 Top1 score。
2. 对空召回或全部 < 0.7 的 query，临时把阈值改为 0.5 重跑一次，记录 Top1 score，判断是“语义不相关”还是“阈值过严”。
3. 若发现阈值 0.7 导致超过 3 条相关结果被过滤，向 Lead 反馈并提出校准建议（如 0.5–0.6 或改用混合检索），不擅自修改线上配置。
